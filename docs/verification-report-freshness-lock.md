# Verification Report Freshness Lock — v2.1.7

v2.1.7 adds the verification report freshness lock.

## verification report freshness lock

The release verifier now suppresses stale report warnings during an active verification run by setting:

```text
VRB_SUPPRESS_STALE_REPORT_WARNINGS=1
```

This prevents previous failed artifacts from polluting the current release log.

## stale report warnings

A stale report warning means an existing artifact was generated by an older or failed run.

It is not a failing gate by itself.

The correct recovery command is:

```bash
npm run verify:all
```

For clean install parity:

```bash
npm run verify:ci-parity
```

## fresh report

A fresh report is generated by the current app version and by a passed gate run.

Expected fresh artifacts:

```text
artifacts/full-qa-gate-report.json
artifacts/release-verify-report.json
```

## warning suppression

Warning suppression applies only to stale artifact warnings inside the release verifier.

It must not suppress failing gates.

It must not suppress syntax errors, lint errors, type errors, build errors, or security/key handling failures.
